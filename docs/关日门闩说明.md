# 关日门闩说明

> 本文件是关日门闩的唯一口径来源。代码内 `GATE_MODE`、`GATE_BODY` 与本文件一致；口径选定后当天不许更换。

## 选定口径：甲门闩

**甲门闩**：关日登记成功即生效。关日后该业务日**一切放行与水位推进硬拒绝**，仅允许只读查询。

**乙门闩**（不采用）：关日后仅允许进入迟到冻结区登记，正式放行与水位仍硬拒绝。

## 硬性约束

1. **服务端裁定**：关日状态只认库内 `day_closes` 记录，页面不得维护本地关日标记，刷新/重开页面不得改变关日结论。
2. **口径独一、不得混卯关**：本仓只落 `mode='甲'`。任何以乙口径写入的请求（改口径关日、迟到冻结区登记）一律拒绝，并在 `gate_audit` 记“关日口径偏了”。
3. **当天不许换口径**：同一业务日重复关日一律拒绝，不得覆盖既有口径。
4. **关日后写入一律硬拒绝**：放行、水位推进、切片登记、完整度重裁、放行流水修订全部 409，仅允许只读查询。
5. **禁止关日后改已放行成功**：对关日后已放行成功记录的修改请求按“关日口径偏了”拒绝并留痕。
6. **同业务日排队互斥**：关日与放行两名值班同时操作时串行化；后手记“关日争用”并拒绝，禁止默认成功。
7. **同库核对**：关日列表、业务目录、切片侧栏、策略旁注、放行流水由同一 `/api/snapshot` 快照读出，关日画面与放行流水读数必须逐日一致。

## 与页面/接口的对应

| 约束 | 落点 |
|------|------|
| 服务端关日表 | `day_closes(biz_date UNIQUE, mode, gate_body, closed_by, closed_at)` |
| 拒绝与争用留痕 | `gate_audit(biz_date, action, actor, result, note)` |
| 统一写入口 | `backend/app.py::run_guarded`（排队 → 写锁 → 门闩裁定 → 写入） |
| 只读快照 | `GET /api/snapshot` |
| 页面 | `frontend/index.html` 关日工作台 |
